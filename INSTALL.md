# Аргус — установка обновления

Архив обновляет действующий проект `argusfinality`. В нём исправление сверки фото,
новая анимация H.264 в 1080 × 720 при 30 кадрах в секунду, оформление бота и панели,
уведомления и кнопки проверки. Архив включает webhook для бесплатного Render.
Используйте его поверх установленной версии «Аргуса» с Telegram-ботом.

## 1. Подготовьте настройки Render

Откройте [Render Dashboard](https://dashboard.render.com/) → сервис
`argusfinality` → **Environment**. Проверьте существующие переменные.

| Переменная | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен от BotFather |
| `DATABASE_URL` | Внутренний адрес вашей PostgreSQL |
| `ADMIN_API_TOKEN` | Ключ для входа в панель, минимум 32 байта |
| `NODE_ENV` | `production` |
| `GEMINI_API_KEY` или другой ключ настроенного провайдера | Значение, которое уже использует анализ |
| `TELEGRAM_WEBHOOK_URL` | `https://argusfinality.onrender.com/api/telegram/webhook` |
| `TELEGRAM_WEBHOOK_SECRET` | Случайный секрет для webhook |
| `ARGUS_FACE_MATCH_ENABLED` | `true` для включения сверки лиц |

Если webhook уже работает, используйте сохранённый секрет. Для новой настройки
создайте отдельный секрет командой в CMD.

```bat
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Вставьте результат в `TELEGRAM_WEBHOOK_SECRET`. Значения ключей храните в Render.
Если доступен вариант **Save only**, сохраните им и переходите к загрузке файлов.

## 2. Загрузите обновление в GitHub

1. В Windows нажмите правой кнопкой на архиве → **Извлечь всё**.
2. Откройте [argusfinality на GitHub](https://github.com/timofeyzhuchev-ctrl/argusfinality).
3. В корне репозитория нажмите **Add file → Upload files**. Перетащите из распакованной
   папки `server.ts` и папки `src`, `public`, `scripts`, `tests`. Убедитесь, что `server.ts` виден
   в корне, `telegramBot.ts` находится в `src/server`, а `processing.mp4` в
   `public/assets/telegram`. Существующие файлы вне архива оставьте в репозитории.
   Проверьте, что в `scripts/face-engine-requirements.txt` указан `numpy==2.3.5`.
   Файлы моделей и Python-библиотеки скачиваются при сборке на Render.
4. Сохраните изменения в ветку, которую использует Render. В предыдущем журнале
   развёртывания это была `main`.
5. В настройках Node-сервиса Render в поле **Build Command** укажите:

   ```sh
   npm install && npm run build && bash scripts/build_face_engine.sh
   ```

   **Start Command** остаётся `npm start`. Разверните последний коммит с полной
   пересборкой. При включённом флаге скрипт установит OpenCV, проверит SHA-256
   моделей YuNet и SFace и запустит их проверку на CPU. Инструкция рассчитана на
   Node-сервис Render, где доступны Python и pip. [Среда Render](https://render.com/docs/native-runtimes#tools-and-utilities)
6. В журнале дождитесь `YuNet and SFace loaded and executed on CPU`,
   `Your service is live` и `[Telegram] Webhook ready`.

## 3. Подключите личный чат администратора

Если `TELEGRAM_ADMIN_CHAT_ID` уже указывает на ваш чат, перейдите к проверке.
Иначе отправьте боту в личном чате `/start`, затем `/myid`. Скопируйте число
из ответа в переменную `TELEGRAM_ADMIN_CHAT_ID` в Render и сохраните с развёртыванием.

## 4. Проверьте после запуска

1. Отправьте `/start`. Появится меню анализа и добавления записи.
2. Отправьте тестовое фото или короткое видео. Во время обработки появится анимация MP4.
   В отчёте виден краткий результат, подробности можно развернуть.
3. Добавьте тестовую заявку. В админ-чате придёт уведомление с её номером,
   ссылкой на панель и кнопками **Одобрить** и **Отказать**.
4. Откройте панель по кнопке и введите `ADMIN_API_TOKEN`. Найдите номер заявки.
   После выбора решения в Telegram нажмите **Обновить** в панели. Фильтры покажут
   заявку в соответствующей группе.
5. Для проверки пробуждения дайте Free-сервису простоять без входящих запросов
   минимум 15 минут и отправьте `/start` при закрытом сайте. Первый ответ может
   задержаться на время пробуждения Render.

## 5. Проверьте сверку по базе

1. Добавьте запись с фотографией одного человека и завершите форму командой `/save`.
2. В личном чате администратора отправьте `/match`, затем тот же файл как фото.
   Если этот файл уже в заявке на проверке, бот сообщит её статус. Нажмите
   **Одобрить** и повторите `/match` с тем же фото. Когда сохранённые байты
   совпадают, отчёт покажет карточку и подпись **«Данные взяты из базы данных „Аргус“»**.
3. Для проверки сравнения лиц отправьте другой снимок того же человека после `/match`.
   Можно также использовать **Управление базой → Сверить лицо с базой «Аргус»**
   и загрузить JPEG, PNG или WebP до 2 МБ. Если запись достаточно похожа, отчёт
   предложит сверить её вручную. При низком сходстве или неоднозначности бот
   покажет соответствующий статус.

Режим `/match` использует локальное сравнение и доступен чату из
`TELEGRAM_ADMIN_CHAT_ID`. Если бот отвечает, что чат администратора не настроен,
проверьте ID через `/myid`. Если показано «Сверка выключена», проверьте
`ARGUS_FACE_MATCH_ENABLED=true` и запустите полную пересборку Render.

Сверка работает на сервере по одобренным фото. Карточку видит администратор.
Дескрипторы для сравнения сохраняются рядом с записями в PostgreSQL. При первом
поиске сервер подготавливает до четырёх фото за запрос. Если показан счётчик
подготовки, повторите сравнение. Лимит этой версии — 100 одобренных записей.

На Windows локально проверены обе модели и сравнение разных снимков одного и
разных людей. Тесты также покрывают ответ о статусе заявки при повторной отправке
файла и работу `/match` без провайдера визуального анализа. Доставку в Telegram и
работу с вашей PostgreSQL нужно проверить после установки. Если движок недоступен,
проверьте строки `[Argus] Face comparison unavailable` и журнал сборки.

Модели берутся из [OpenCV Zoo](https://github.com/opencv/opencv_zoo/tree/48b10fa505aeb51fbd127fc60a5c660040e823b7/models).

На поддерживающих клиентах Telegram действия выделяются цветом. Подписи видны
и в клиентах с обычным оформлением. При проблеме с уведомлением сначала проверьте
`TELEGRAM_ADMIN_CHAT_ID` и сообщения `[Telegram]` в Render Logs.
