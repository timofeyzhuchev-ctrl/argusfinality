# Telegram: добавление записей

## Оформление бота

После обновления сервера и команды `/start` появляется меню с кнопками
«Анализ фото», «Анализ видео», «Добавить запись», «Помощь». В форме добавления
кнопки меняются на «Пропустить», «Отмена» и «Сохранить», отображается номер шага.
Во время анализа одно сообщение обновляется раз в 4 секунды: движется маркер,
отображается текущая стадия и Telegram-индикатор «печатает». После завершения
тот же блок превращается в результат. Индикатор не показывает выдуманный процент
готовности. При ошибке оформления обработчик анализа продолжает работу.

Сервер устанавливает меню команд через `setMyCommands` при запуске. Аватарка,
название в профиле и фон чата не изменяются. Для проверки этой версии:
`node --test tests/telegramRegistration.test.mjs tests/telegramPresentation.test.mjs`
(Node 24) или та же команда через `npx tsx --test` на Node 22.

В этой версии реализовано добавление через `/add` в ту же таблицу
`argus_shared_records`, которую использует сайт. Перенос старых данных не выполняется.
Анализ фото и видео в этом изменении не переделан.

## Пользовательский сценарий

1. Открыть личный чат с ботом, отправить `/add`.
2. Ввести ФИО, затем дату рождения (ДД.ММ.ГГГГ или ГГГГ-ММ-ДД).
3. Ввести организацию и ссылку VK либо пропустить каждое поле через `/skip`.
4. Отправить фотографию как фото, не документ, до 2 МБ.
5. Проверить текст и отправить `/save`. Только после ответа базы бот подтвердит сохранение.
6. Запись появится в административной панели сайта со статусом «Ожидает проверки».

`/cancel` отменяет ввод, `/add` начинает заново. Вне добавления фотографии и видео
поступают в прежний обработчик анализа. Черновик хранится в памяти не дольше
15 минут бездействия и теряется при перезапуске. Сохранённая запись остаётся в PostgreSQL.
При ошибке базы можно повторить `/save`: ID заявки сохраняется, дубль не создаётся.

## Переменные сервера

- `TELEGRAM_BOT_TOKEN`: уже созданный токен BotFather.
- `DATABASE_URL`: подключение к PostgreSQL, общее для сайта и бота.
- `ADMIN_API_TOKEN`: секретный случайный ключ минимум 32 байта; используется
  владельцем в панели «Управление базой». Не передавайте его пользователям бота.
- `NODE_ENV=production` и существующие переменные нейросети сохраняются.

Секреты вводятся только в Render Environment, не в GitHub. Таблица создаётся при
первом обращении к базе; пользователь PostgreSQL должен иметь право её создать.

Бот использует long polling: запускайте только один экземпляр этого сервиса,
и не запускайте одновременно другого бота с тем же токеном. Существующий webhook
для этого токена должен быть отключён. На засыпающем сервере сообщения Telegram
не гарантируют пробуждение — нужен постоянно работающий экземпляр.

## Проверка перед публикацией

В локальном checkout с Node.js >=22.12 выполните `npm install`, затем
`npm run lint` и `npm run build`. Для тестов добавления: `npx tsx --test tests/telegramRegistration.test.mjs`.
При использовании Node 24 эти тесты запускаются также командой
`node --test tests/telegramRegistration.test.mjs`.

Шесть изолированных тестов сценария добавления прошли на Node 24. Синтаксис
серверных файлов проверен. Полная сборка и реальная отправка в Telegram/PostgreSQL
не проверены в среде подготовки. Перед обновлением действующего сервиса проверьте
версию в отдельном окружении с тестовым ботом и тестовой базой.

Архив содержит текущий проект целиком. Для Render Node build command —
`npm install && npm run build`, start command — `npm start`. Для Docker применяется
существующий Dockerfile. Ветка GitHub и Render этой работой не обновлялись.

## Границы версии

Поиск человека по фотографии всё ещё не реализован; прежние недостоверные
подтверждения личности отключены в подготовленной версии. Добавление записи не
является проверкой личности. Просмотр всех записей и одобрение доступны только
администратору; редактор отдельных полей пока не реализован. Лимиты добавлений
действуют в памяти одного процесса и сбрасываются при перезапуске.
